# Deployment Guide

This document explains how to deploy the OpenBudget Dashboard to GitHub Pages with automated data updates.

## Architecture

The deployment uses two GitHub Actions workflows:

1. **deploy.yml** - Initializes database and deploys on push to master
2. **data-download.yml** - Updates budget data daily and redeploys

**Note**: The `budget.duckdb` file is **not committed** to the repository. It's generated/updated by GitHub Actions on each deployment.

## Initial Setup

### 1. Enable GitHub Pages

1. Go to your repository on GitHub
2. Navigate to **Settings** → **Pages**
3. Under **Build and deployment**, select:
   - **Source**: GitHub Actions
4. Save the settings

### 2. Push the Workflows

```bash
git add .github/workflows/*.yml DEPLOYMENT.md .gitignore
git commit -m "feat: add GitHub Actions deployment workflows"
git push
```

### 3. Initial Deployment

The first push will trigger `deploy.yml`, which will:
1. Initialize the database by downloading data from OpenBudget API
2. Build the site
3. Deploy to GitHub Pages

This first deployment will take **15-30 minutes** depending on data size.

## Automated Data Updates

The `data-download.yml` workflow runs **daily at 2 AM UTC** and:

1. Updates the budget database using `update-db.R`
2. Builds the site with fresh data
3. Deploys to GitHub Pages

### Manual Data Update

You can manually trigger a data update:

1. Go to **Actions** → **Update Budget Data**
2. Click **Run workflow**
3. Select the branch (master)
4. Click **Run workflow**

## Workflows Overview

### deploy.yml (Push-triggered)

- **Trigger**: Push to master branch
- **Purpose**: Deploy after code changes
- **Steps**:
  1. Checkout repository
  2. Setup R environment
  3. Initialize database (if not exists)
  4. Setup Node.js
  5. Build site
  6. Deploy to GitHub Pages
- **Duration**: ~15-30 minutes (first run), ~5-10 minutes (subsequent)

### data-download.yml (Scheduled)

- **Trigger**: Daily at 2 AM UTC (or manual)
- **Purpose**: Automated data updates
- **Steps**:
  1. Checkout repository
  2. Setup R environment
  3. Initialize or update database
  4. Setup Node.js
  5. Build site with fresh data
  6. Deploy to GitHub Pages
- **Duration**: ~10-20 minutes

## Configuration

### Changing Update Schedule

Edit `.github/workflows/data-download.yml`:

```yaml
on:
  schedule:
    - cron: '0 2 * * *'  # Daily at 2 AM UTC
```

Common schedules:
- `0 2 * * *` - Daily at 2 AM
- `0 2 * * 1` - Weekly on Monday at 2 AM
- `0 2 1 * *` - Monthly on 1st at 2 AM

### Adding New Cities

To add data for a new city, edit `src/data/config.yaml`:

```yaml
cities:
  - 8000000000 # Kyiv
  - 4610100000 # Cherkasy
  - 1210100000 # Dnipro
  - 5910100000 # New City Code
```

Then trigger the data update workflow manually.

## Monitoring

### Check Workflow Status

1. Go to **Actions** tab in your repository
2. View recent workflow runs
3. Click on a run to see detailed logs

### Troubleshooting

**Deployment fails with "No GitHub Pages environment":**
- Go to Settings → Pages
- Ensure "Source" is set to "GitHub Actions"

**Data update fails:**
- Check the workflow logs in Actions tab
- Look for R script errors in "Initialize or update database" step
- Check OpenBudget API availability
- Verify cities configuration in `config.yaml`

**Site shows old data:**
- Wait for deployment to complete (~5 minutes after workflow finishes)
- Clear browser cache (Cmd+Shift+R)
- Check Actions tab to confirm deployment succeeded

**First deployment takes too long:**
- This is normal! Downloading and processing budget data takes time
- Check workflow progress in Actions tab
- First run: 15-30 minutes
- Subsequent runs: 5-10 minutes

## File Structure

```
.github/workflows/
  ├── deploy.yml         # Deploy on push (with DB initialization)
  └── data-download.yml  # Scheduled data updates

src/
  ├── index.md           # Home page
  ├── budget-dashboard.md
  └── data/
      ├── budget.duckdb  # Generated by GitHub Actions (not in repo)
      ├── update-db.R    # Data update script
      └── config.yaml    # Cities configuration
```

## Why Database is Not Committed

The `budget.duckdb` file (40+ MB) is **excluded** from the repository because:

1. **GitHub has size limits** - Large files cause push failures
2. **Generated content** - It's rebuilt from source data on each deployment
3. **Always fresh** - GitHub Actions fetches latest data directly from API
4. **Reduces repo size** - Keeps repository lightweight and fast to clone

The database is generated automatically by GitHub Actions during each deployment.

## Security Notes

- The workflows use secure environment variables
- Database updates use parameterized SQL queries
- No sensitive credentials are stored in the repository
- All API calls are read-only to OpenBudget API
